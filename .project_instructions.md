## Agora Live Streaming Integration (with Beauty Effects)
- Replaced P2P WebRTC with Agora.io managed streaming SDK
- Package: `agora-rtc-sdk-ng` (browser-only, must be lazily imported via dynamic `import()`)
- Token server: `/api/agora/token` - generates RTC tokens using `agora-token` package
- Client helper: `lib/agora-client.ts` - async `createAgoraClient()`, `createLocalTracks()`, `fetchAgoraToken()`, `leaveChannel()`, `getCameras()`
- Channel naming: `stream_${streamId}` per broadcast
- Broadcaster page (`/sohbet/video/broadcast/[streamId]`): host role, publishes local audio+video tracks
- Viewer page (`/sohbet/video`): audience role, subscribes to remote tracks
- Agora plays video into div containers (not native `<video>` elements) - use `[&_video]:w-full [&_video]:h-full [&_video]:object-cover` CSS
- SSR safety: `agora-rtc-sdk-ng` cannot be imported at module level (no `window` in SSR). All imports are async/dynamic.
- Setup page still uses old webrtc-config for camera preview (intentional), with canvas-based beauty preview
- All HTTP polling features preserved: gifts, comments, likes, fortune requests, co-broadcasting, moderators, stats
- Env vars: AGORA_APP_ID, AGORA_APP_CERTIFICATE, NEXT_PUBLIC_AGORA_APP_ID
- Beauty Effects: Uses Agora SDK built-in setBeautyEffect() on ICameraVideoTrack
  - lib/agora-client.ts: AgoraBeautySettings, DEFAULT_BEAUTY_SETTINGS, BEAUTY_PRESETS (6 presets), applyBeautyEffect()
  - Settings: smoothnessLevel/lighteningLevel/rednessLevel (0-1), lighteningContrastLevel (0/1/2)
  - Setup page: canvas preview with presets+sliders; Broadcast page: real Agora effects with live panel
  - Persisted in localStorage as agoraBeautySettings

## PK Battle System (TikTok-style)
- DB model: PKBattle (stream1Id, stream2Id, user1Id, user2Id, score1, score2, status, duration, startedAt, winnerId)
- API routes: /api/video-streams/pk (GET/POST: create, accept, reject, cancel, end), /api/video-streams/pk/score, /api/video-streams/pk/list
- Gift endpoint auto-updates PK scores when gift is sent during active PK
- PK overlay component: components/pk-battle-overlay.tsx (progress bar, timer, scores, winner animation)
- Broadcaster: PK button in controls → select opponent from live broadcasters, set duration (1/3/5/10 min)
- Viewer: sees PK overlay with live scores, progress bar, timer
- PK flow: create → pending (waiting accept) → active (timer running) → completed (winner shown)
- Admin tap scoring: Admin/yonetici users can tap screen during active PK → every 3 taps = 3 PK points via /api/video-streams/pk/score. Only works when pkBattle.status === 'active'. Uses pkTapCountRef, resets on PK status change.

## Chat System (Sohbet)
- Chat rooms with real-time messaging via SSE (Server-Sent Events)
- IRC-style permission hierarchy: `%` superadmin (strongest) > `~` founder > `&` SOP > `@` op > `+` voice
- Global admins (admin/moderator/site_manager) auto-get `superadmin` (%) role in any room
- Room owners get `founder` (~) role
- Old 'admin' DB role maps to 'sop' for backward compatibility
- Room settings API: /api/chat/rooms/[roomId]/settings (founders+ can manage)
- Midnight cleanup: /api/chat/cleanup deletes ALL messages (Turkey time 00:00 = UTC 21:00)
- Admin panel: /admin/chat-rooms has commission rate (%) and room mute toggle in edit modal
- Key files: lib/chat-permissions.ts, app/[lang]/sohbet/[roomSlug]/page.tsx (2700+ lines)
